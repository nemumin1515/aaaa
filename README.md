# かぐや姫のむちゃぶり御前

5人までの求婚者がスマートフォンから参加し、現代の日用品を「本物の宝物」と言い張るボケを競うWebゲームです。

## 遊び方

1. このフォルダーの中身をGitHub PagesなどのHTTPS対応Web公開先へアップロードします。
2. 親PCで公開ページを開き、「部屋を作る」を押します。
3. 表示されたQRコードをスマートフォンで読み取り、ニックネームを入力します。
4. 参加者がそろったら、親PCで「準備を始める」→「提出スタート」と順に押します。
5. スマートフォンで日用品とボケを入力して提出します。
6. 親PCで「提出を締め切る」→「全員へ一斉公開」へ進み、各ボケに0〜3点を付けます。姫のひと言は手入力できます。空欄なら点数に応じた短いツッコミが付きます。
7. 「結果を発表する」で点数を公開し、「次の宝物へ」で全5問を遊びます。

## GitHub Pagesへ置く場合

公開前の注意：GitHub Pagesの画面はインターネット上に公開されます。ゲーム中は親PCのページを閉じないでください。

1. GitHubで新しいリポジトリを作ります。既存の別ゲームに上書きしないよう、このゲーム専用のリポジトリがおすすめです。
2. ZIPを解凍し、`kaguya-gag-game`フォルダー**内**の`index.html`、`README.md`、`assets`フォルダーをリポジトリの一番上にアップロードします。`index.html`が一番上にある配置です。
3. リポジトリの「Settings」→左メニュー「Pages」を開きます。
4. 「Build and deployment」の「Source」で「Deploy from a branch」を選びます。「Branch」を`main`、フォルダーを`/(root)`にして「Save」を押します。
5. 表示された公開URLを親PCで開き、「部屋を作る」を押します。スマートフォンにはその画面のQRコードを見せます。

## 通信と復帰

- スマートフォンは親PCのPeer IDに接続します。スマートフォン同士は接続しません。
- ゲームの進行、参加者、提出内容、得点は親PCが管理します。
- 参加者IDとニックネームはスマートフォンのブラウザー内に保存します。同じブラウザーで再読み込みした場合は、元の参加者IDで再接続します。
- 画面ロックなどで接続が閉じても、ホストは90秒間「復帰待ち」として席を保持します。スマートフォンが画面に戻ると再接続を試みます。
- ホストPCのページを再読み込み・終了すると、部屋と進行中データは失われます。ゲーム中はホストのページを開いたままにしてください。

## 公開・動作条件

- PeerJSとQRコードのライブラリーをCDNから読み込むため、ホストPCとスマートフォンの両方でインターネット接続が必要です。
- PeerJSのシグナリングサービスは接続先の案内に使います。実際のデータ通信はWebRTCのDataConnectionです。
- スマートフォンでQR参加するには、GitHub PagesなどのHTTPSで開けるURLが必要です。PC内のファイルを直接開く方法では参加URLをスマートフォンへ渡せません。
- ネットワークの制限やNATの種類によってWebRTC接続できない場合があります。この版ではTURNサーバーを設定していません。
- ホストのタブを閉じるとゲームが終了します。参加者は同じ端末・同じブラウザーで戻ってください。別端末や別ブラウザーでは別参加者として扱われます。

- `assets/`：舞台、かぐや姫、5つの宝物の画像
